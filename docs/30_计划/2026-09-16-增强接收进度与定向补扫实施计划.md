# 增强接收进度与定向补扫 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans in the current conversation by default. Use subagent-driven-development only when delegation is authorized by the user or applicable workflow.

**Goal:** 为增强 RaptorQ 模式增加源符号进度框和遗漏二维码定向补扫。

**Architecture:** 核心层统一计算 RaptorQ source layout、Payload ID、聚合进度和 `RQ1` 请求码；解码 Worker 维护源符号覆盖；接收 UI 生成请求；发送 UI 用请求过滤播放顺序。二维码线协议、CRC32C 和最终 SHA-256 不变。

**Tech Stack:** TypeScript、Preact、Web Worker、RaptorQ WASM、Vitest、Playwright、单文件 Vite 构建。

### Task 1: Recovery request core

- [x] 写 source layout、范围编解码、请求校验和 packet 选择失败测试。
- [x] 实现 `raptorq_recovery.ts` 并使测试通过。

### Task 2: Decode progress and request generation

- [x] 写 Worker 进度桶与遗漏 source IDs 测试。
- [x] Worker 维护 source bitset、repair count，并响应 recovery request。
- [x] 接收 UI 增加进度条、覆盖格、遗漏计数、生成/复制请求。

### Task 3: Sender missing-only playback

- [x] 发送 UI 增加请求输入；生成传输后仅调度缺失 source packets。
- [x] 请求参数不匹配或没有可补扫包时显示明确错误。
