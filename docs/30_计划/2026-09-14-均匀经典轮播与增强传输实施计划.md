# 均匀经典轮播与增强传输 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans in the current conversation by default. Use subagent-driven-development only when delegation is authorized by the user or applicable workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复经典文件首片密度，并交付完全独立、自包含的 RaptorQ 多二维码增强发送端和接收端。

**Architecture:** 经典页面新增 `Q3F` 等长分片协议且继续接收 V2；增强页面由固定版本的 RaptorQR 源码构建，使用内联 Worker/WASM、应用级 SHA-256 信封与可选前后摄像头。两套协议、状态和页面完全隔离，只由首页导航关联。

**Tech Stack:** 静态 HTML、JavaScript/TypeScript、QRCode.js、jsQR、RaptorQ WASM、fast_qr WASM、ZXing-C++ WASM、Vite、Vitest、Playwright。

## Global Constraints

- `sender.html`、`receiver.html`、`sender-fast.html`、`receiver-fast.html` 均必须是单文件自包含运行产物。
- 生产页面不得包含 CDN、外部 JavaScript/WASM、动态 import、运行时 fetch 或服务端接口。
- 经典接收端必须继续兼容现有 V2 传输。
- 增强模式默认双码，提供单码和四码。
- 增强模式每包 CRC32C、最终 SHA-256，损坏数据不得下载。
- 不修改或删除主工作区现有未跟踪文件。
