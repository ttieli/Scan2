# 均匀经典轮播与增强传输设计

## 目标

在不破坏现有二维码顺序轮播的前提下完成两条相互隔离的能力：

1. 经典发送端改用均匀文件分片，使元数据不再集中在第一张二维码，整轮二维码保持相同容量与模块密度；接收端继续兼容既有 V2 文件。
2. 新增独立的增强发送端和增强接收端，使用 RaptorQ、CRC32C、单/双/四二维码播放、多码识别和最终 SHA-256 校验，并支持 iOS Safari 前置与后置摄像头。

所有生产页面均为单个、自包含 HTML，不包含运行时 CDN、外部脚本、外部 WASM、动态模块或服务端接口。

## 产品边界

### 经典模式

- `sender.html` 和 `receiver.html` 保留当前 UI、补传和 V2 接收能力。
- 文件发送改为 V3 均匀串行协议；文本协议不变。
- V3 把元数据 JSON 与 Base64 文件数据拼成一个逻辑对象后等长切片，第一片只承载该对象的普通前缀。
- V3 每个 QR 使用固定宽度 ASCII 头和固定长度载荷，末片填充后按对象真实长度裁剪；同一传输的 QR 版本保持一致。
- 接收端识别 `Q3F` magic 后进入独立 V3 状态，不与 V2 状态混合；完成后解析元数据、校验大小和 SHA-256。

### 增强模式

- 新增 `sender-fast.html` 与 `receiver-fast.html`，不调用经典模式的协议、状态和持久化函数。
- 增强模式基于固定上游提交 `infrost/RaptorQR@fdb434e1fc1126f84b98e407be8d24bbb683b597`，保留 MIT 许可证和来源说明。
- 发送链：文件/文本 → 完整性信封 → 可选压缩 → RaptorQ → 8 字节传输头 + CRC32C → QR → 1/2/4 码播放。
- 接收链：摄像头帧 → ZXing-C++ WASM 多码识别 → CRC32C → 去重 → RaptorQ WASM → 解压 → 完整性信封和 SHA-256 → 文件/文本。
- 默认参数为双码、RaptorQ、Balanced 播放；单码用于稳健场景，四码为大屏极速档。
- 前后摄像头通过 `facingMode: { exact }` 首选、`{ ideal }` 回退；切换摄像头前必须停止旧 track。

## 自包含构建

增强模式的可维护源码放在 `fast-mode/`。Vite 构建时使用单文件插件，并把四个 Worker 以 Blob worker 内联、把 fast_qr、RaptorQ、ZXing reader/writer WASM 以内联 data URL 打包。构建产物只允许一个 `index.html`；该产物复制为两个独立页面，接收端页面在加载前设置 `#receiver`。

增强页面不得注册 Service Worker、读取 manifest/icon 或预加载相邻文件。构建完成后执行静态扫描和请求拦截测试，证明页面自身不会请求其他运行时资源。

## 完整性信封

增强模式在进入 RaptorQ 前加入应用信封：

```text
magic(4) + version(1) + kind(1) + originalLength(4)
+ sha256(32) + filenameLength(2) + mimeLength(2)
+ filename + mime + original bytes
```

- SHA-256 覆盖用户原始字节，不覆盖文件名和 MIME。
- 文件名和 MIME 使用 UTF-8，长度按字节计算。
- 解码端先验证信封边界和原始长度，再计算 SHA-256；不一致时不得提供下载或文本。
- CRC32C 负责逐包拒绝损坏，RaptorQ 负责丢包恢复，SHA-256 负责最终字节一致性，三者职责不混用。

## iOS Safari 摄像头

- 启动扫描必须来自按钮点击。
- 默认后置；用户可在启动前选择前置。
- 申请 `exact` 失败时仅对 `OverconstrainedError`/`NotFoundError` 回退到 `ideal`，权限拒绝不得静默重试。
- 页面非安全上下文或 `mediaDevices` 不可用时显示明确错误。
- 前置预览可以镜像，传给识别 Worker 的像素保持未镜像原图。

## 测试与验收

1. 经典 V3 的长中文文件名、首/中/末片 QR 模块数一致，随机二进制字节往返和 SHA-256 通过。
2. 经典 V2 原有 26 项测试全部通过。
3. 增强完整性信封正常往返；任意数据位被修改后 SHA-256 校验失败。
4. CRC32C 损坏包在进入 RaptorQ 前被拒绝。
5. 模拟乱序、重复和丢失源符号时，RaptorQ 依靠 repair symbols 恢复原文。
6. 1/2/4 码调度不丢包、不重复分配同一显示槽；默认值为 2。
7. 前置约束首先请求 `user`，后置首先请求 `environment`，切换前停止旧流。
8. `sender-fast.html`、`receiver-fast.html` 各自只需自身文件即可加载，网络请求列表为空，控制台无错误。
9. iOS Safari 真机验证作为交付后的设备门槛；自动化只能验证约束、回退和页面状态，不能替代真实摄像头光学测试。

## 非目标

- 不把增强协议塞入经典 V2 状态机。
- 不保证四码始终比双码快；实际 goodput 由设备、屏幕、距离与光线决定。
- 不增加服务器、上传、账户、网络传输或双向 ACK。
- 本轮不突破既有文件大小保护上限。
