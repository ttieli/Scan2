# 增强接收进度与定向补扫设计

## 目标

为增强 RaptorQ 模式补回经典模式中最有价值的两个交互：可视化接收进度框，以及只播放遗漏二维码的定向补扫。

## 设计

RaptorQ 的 repair symbol 可以替代缺失 source symbol，因此进度框分为两层：

- 总体解码进度：已接受有效包 / 预计所需包。
- 源符号覆盖图：直接收到的 source symbol 以最多 200 个聚合格展示；repair symbol 数量单独显示。

接收端能够从 `dataLength`、symbol size 与每包前 4 字节 Payload ID 推导完整 source symbol 集合。用户点击“生成补扫请求”后，接收端输出 `RQ1` 请求码，其中包含传输参数和尚未直接收到的 source Payload ID 范围。

发送端粘贴请求码并重新开始播放时，使用完整确定性 RaptorQ 包集查找对应 source packets，只循环这些包。请求码的数据长度或 symbol size 与当前文件不一致时拒绝应用。空请求表示无需补扫。

## 请求格式

```text
RQ1|<dataLength-base36>|<symbolSize-base36>|<block>=<esi-ranges>[;<block>=...]
```

示例：`RQ1|9ix|ng|0=2-5,8;1=0-3`。

该请求不包含文件内容，只包含缺失 source symbol 标识。最终文件仍必须通过完整 SHA-256；请求码只用于调度，不改变协议安全边界。

## 验收

- RaptorQ worker 进度消息包含 source 总数、已收 source、repair 数量和聚合桶。
- 接收页面显示总体进度条、源符号覆盖格和遗漏数量。
- 请求码可复制，并能由发送端解析为准确的 canonical packet indexes。
- 发送端请求与当前文件参数不匹配时拒绝。
- 应用请求后仅循环缺失 source packets，单/双/四码布局继续可用。
- 既有 RaptorQ、CRC32C、SHA-256、自包含和经典 29 项回归全部通过。
