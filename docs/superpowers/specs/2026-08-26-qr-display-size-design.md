# QR 显示尺寸与移动端文件操作优化设计

## 目标

降低循环播放和单张显示共用的全屏覆盖层二维码尺寸，并允许用户即时调节；同时修复 iOS Safari、iOS WebView 与 Android 浏览器中 Blob 下载不可靠、反馈失真和下载后无法找到文件的问题。网格平铺、二维码载荷、纠错级别和 V2 协议不变。

## 现状与问题

- 私有二维码通常以 200px 生成，公有二维码以 300px 生成。
- 循环模式对整个 `.qr-item` 再应用 `scale(1.5)`，公有二维码最终可达到约 450px。
- 单张模式直接沿用生成时的像素尺寸，没有独立、统一的显示尺寸设置。
- 二维码生成尺寸与显示尺寸耦合，导致不同协议类型在相同模式下视觉大小不一致。

## 交互设计

在循环播放和单张显示共用的全屏覆盖层增加“二维码尺寸”控制：

- 控件：原生 `range` 滑杆。
- 范围：160–360px。
- 步进：20px。
- 默认值：220px。
- 当前值：在滑杆旁实时显示，例如 `220px`。
- 循环播放和单张显示共用同一个值。
- 用户调整后立即更新当前显示，不重新生成 QR 数据。
- 使用 `localStorage` 保存最后一次选择；保存值损坏、越界或无法读取时回退到 220px。

网格平铺不显示该控件，也不受该值影响。进入循环或单张覆盖层后，滑杆保持可见并即时调整 `#singleQRContent` 内的二维码；退出覆盖层后隐藏。

## 实现方式

### 显示与生成解耦

保留 QRCode.js 当前生成结果，不为每次滑杆变化重新编码。通过 CSS 自定义属性控制全屏覆盖层内二维码画布、图片或 SVG 的可视宽高：

```css
#singleQRContent > div:first-child,
#singleQRContent canvas,
#singleQRContent img,
#singleQRContent svg {
    width: var(--display-qr-size);
    height: var(--display-qr-size);
}
```

具体选择器必须同时覆盖 QRCode.js 可能生成的 `canvas`、`img` 和 `svg`，并保持 1:1 比例。移除循环模式的 `transform: scale(1.5)`，避免标签、卡片留白和按钮一起被放大。

### JavaScript 状态

新增单一状态值 `displayQRSize`：

- 初始化时从 `qr_display_size` 读取并校验。
- `setDisplayQRSize(value)` 负责截断到 160–360、对齐 20px 步进、更新 CSS 变量和数值标签，并尝试写入 `localStorage`。
- `enterSingleMode()` 和循环覆盖层负责显示尺寸设置；`exitSingleMode()` 与网格模式隐藏。
- `showQRCode()`、循环换页和指定编号补传不得覆盖尺寸值。
- 语言切换只更新标签文字，不改变数值。

## 响应式约束

- 在窄屏设备上，实际显示宽度不得超过覆盖层可用宽度，使用 `min(var(--display-qr-size), calc(100vw - 80px), calc(100vh - 230px))` 或等效 CSS。
- 高度与宽度保持一致，不拉伸二维码。
- 标签保持原字号，不随二维码尺寸缩放。
- 220px 默认值应在 iPhone 竖屏、桌面浏览器和分屏窗口中无需横向滚动。

## 移动端文件操作

网页无法读取或强制指定 Safari、Chrome 或系统的默认下载/打开/转发规则，因此使用能力检测提供三条明确路径。

### 统一文件对象

SHA-256 校验通过后，以原始文件名、原始 MIME 和字节创建一次 `File`：

```js
new File([verifiedBytes], fileName, { type: originalMime || 'application/octet-stream' })
```

分享、直接下载和预览均复用该对象，避免当前强制 `application/octet-stream` 导致的未知文件类型和预览失效。

### 分享 / 存储文件

- 当 `navigator.share`、`navigator.canShare` 存在且 `navigator.canShare({ files: [file] })` 返回 `true` 时显示主按钮“分享 / 存储文件”。
- 分享参数只传 `{ files: [file] }`，避免部分 iOS Safari 版本同时传标题或文本时拒绝文件分享。
- 必须由用户点击触发；`AbortError` 视为用户取消，不显示失败警告。
- Promise 成功只代表系统分享面板流程结束，不假定用户一定保存；保留当前接收会话和文件，可再次操作。

### 直接下载

- 所有平台保留“直接下载”作为后备。
- 使用 `File` 的真实 MIME 创建 Blob URL，并设置原始文件名为 `download`。
- 触发点击后不再在 100ms 内撤销 URL。链接节点可延迟移除，Blob URL 至少保留 60 秒；页面销毁时交由浏览器释放，避免 `pagehide` 再次过早撤销。
- 文案使用“已请求下载，请检查浏览器下载项”，不声称已经保存成功。
- 直接下载后不清除传输会话。

### 打开预览

- 仅对 `application/pdf`、`text/*`、`image/*`、`audio/*`、`video/*` 显示“打开预览”。
- 在用户点击的同步调用链中打开新标签，再赋值 Blob URL，降低移动浏览器弹窗拦截概率。
- 压缩包、可执行文件和未知二进制不提供预览。
- 预览 URL 使用与直接下载相同的延迟回收机制。

### 状态与提示

- 文件完成后根据能力显示：主操作“分享 / 存储文件”（如支持）、“直接下载”、以及按 MIME 出现的“打开预览”。
- iOS 提示：“在文件 App → 下载项中查找；实际位置由 Safari 下载项设置决定。”
- Android/桌面提示：“请检查浏览器下载列表或系统文件管理器。”
- 只有用户点击“重新扫描”才清除已接收文件；下载、预览、分享成功或取消均不自动清除。

Safari 通常把文件保存到“文件”App中的“iCloud Drive/下载项”，用户也可以在“设置 → App → Safari → 下载项”改成“我的 iPhone”或其他位置。

参考：

- <https://support.apple.com/en-mide/102440>
- <https://support.apple.com/guide/iphone/customize-your-safari-settings-iphb3100d149/ios>

## 测试

新增生产发送端回归测试，至少覆盖：

1. 默认尺寸为 220px。
2. 160、220、360 三个合法值即时生效。
3. 小于 160、大于 360、非数字和损坏的持久化值正确回退或截断。
4. 循环与单张模式共用设置；网格模式不应用该尺寸。
5. 切换 QR 页、暂停/继续、补传和重新生成后尺寸保持。
6. 循环和单张共用的全屏容器即时应用尺寸，滑杆在覆盖层中可操作。
7. 移除循环模式 `scale(1.5)` 后，二维码标签和卡片不再被整体放大。
8. 现有 15 项 V2、QR 标准兼容、安全和生产往返测试继续通过。
9. 支持文件分享的平台显示“分享 / 存储文件”；不支持时不显示且直接下载仍可用。
10. PDF、文本、图片、音视频显示预览；其他 MIME 不显示。
11. 直接下载使用原始文件名/MIME，Blob URL 清理延迟至少 60 秒。
12. 下载、分享和预览均不清除活动文件会话。
13. 分享取消不报错；真正异常提供可操作提示。
14. 自动测试验证按钮能力分流、File 元数据、URL 生命周期和反馈文案；不再只验证下载按钮是否启用。

## 非目标

- 不调整网格平铺二维码尺寸。
- 不改变覆盖层的分页、暂停、补传和键盘操作。
- 不改变二维码版本、数据容量、纠错级别、分片数量或扫描协议。
- 不尝试从网页读取或指定浏览器的真实下载目录、默认打开应用或默认转发目标。
- 不引入服务器下载接口、Service Worker、PWA 安装要求或外部文件保存库。

## 成功标准

- 循环和单张模式初次打开均以 220px 显示。
- 用户可在 160–360px 范围内调节，刷新后保留。
- 公有与私有二维码在同一显示模式下使用一致的可视尺寸。
- 网格不受尺寸设置影响；循环和单张覆盖层正确应用尺寸且无操作回归。
- iOS Safari/Chrome/Firefox、Android Chromium 和桌面浏览器均至少具备一条可用文件操作路径。
- Web Share 支持时可进入原生“分享 / 存储”面板；不支持时直接下载保持可用。
- 文件操作后仍可再次下载、预览或分享，不因一次失败丢失已接收数据。
- 全套自动测试连续运行通过，生产页面无控制台错误。
